4.1 项目来源

新增 src/host/catalog.js，合并两个来源并按路径去重：

  • ctx.workspaceRegistry.list()：DSH 已登记的全部工作区，包含 path、title、sessionIds、updatedAt。这是「所有项目」的主来源。

07编辑能力

7.1 三层编辑

层级交互改动范围宿主动作默认
L1 条目点条目进入单行编辑，Enter 保存 / Esc 取消；行尾编辑、删除单条edit / remove开（已有，优化交互）
L2 小节小节标题右侧「编辑小节」→ 该小节原始内容 textarea → 保存一个小节新增 replace-section开（需面板写操作）
L3 源码文档头「源码」→ 整文件 textarea + 结构校验 + diff 统计整个文件新增 replace-document开（首次进入二次确认）
新建小节文档头「新建小节」→ 标题 + 第一条新增 ##复用 add开
删除小节小节菜单「删除小节」→ 确认 + 备份一个小节新增 remove-section开
撤销保存 / 删除后 Toast「撤销」，10 秒整文件复用 restore开
L1 为什么不做多行
Markdown 解析器只把 - 开头的行当条目；多行 textarea 写进去的续行不会被解析，等于写入「看不见的死内容」。所以 L1 保持单行输入，多行需求走 L2 小节编辑。

7.2 一次保存的完整流程

1
进入编辑态，锁定 revision
面板记住当前文件 revision 与该条目行号；不锁文件，只记「我看到的是这一版」。
2
本地草稿
输入即草稿，不自动保存；切换文件时若有未保存内容先确认。
3
提交 POST /action
带 expectedRevision、target、section、line / replacement；进同一个 write()：加锁 → 锁内二次哈希 → 备份 → 原子写。
4
成功：Toast + 撤销
行闪一次高亮，状态条刷新，10 秒内可撤销；提示「已保存，下一轮对话生效」。
5
冲突：草稿不丢
二次哈希不符不写；弹「重新加载 / 查看差异 / 覆盖（先备份）」三选一，默认聚焦重新加载。

7.3 新增宿主动作与校验

动作参数校验
replace-sectiontarget、section、body、expectedRevision小节仍存在；正文里没有新的 # 标题；非空行必须是 - 条目（允许缩进子项）
replace-documenttarget、text、expectedRevisionUTF-8、无 NUL、代码围栏成对、大小 ≤ 256KB；保存前显示「+N / -M 条」变化量
remove-sectiontarget、section、expectedRevision小节存在；删除前备份；返回被删条目数
安全边界不变
所有新动作仍然走 writeEverywhere：同一把锁、同一个 expectedRevision、同一份备份、同一本 operation log。UI 只负责把参数填好，不新增任何写文件通道。
