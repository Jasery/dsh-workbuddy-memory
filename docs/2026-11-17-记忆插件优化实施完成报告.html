三、实施过程中拦下的真实问题

以下每一项都经过复现，不是推测；其中多项在原方案里被写成「已正确」或未被识别。

  1. 配置显式值被吞成默认：readOnly:true 经 schema 后变 false，workbuddyHome 回退空值。
  2. 同操作号并发写两份：去重在锁外预查，两个排队请求各写一次。
  3. 备份同毫秒互相覆盖：文件名只有毫秒时间戳，初始版本丢失。
  4. 归档不绑定预览集合：预览后新增的旧文件会被一起移走；预览后修改的内容被直接归档。
  5. 读取竞态返回片段版本：预检后文件增长，仍返回前 2 MiB 的 hash。
  6. 空文件被迁移守卫卡死：0 字节 MEMORY.md 首次写入永远被拒。
  7. 核心超额静默丢弃：12 条只进 7 条，无提示、状态仍显示正常。
  8. 英文规则超限截断：2009 > 2000，丢掉「日期流水别搬进 MEMORY.md」那条。
  9. 源码冲突丢失出口：修遮罩时误删「看差异 / 保留草稿」，只剩会丢草稿的重载。
  10. 面板无法切回 full：设计承诺的排障出口没有控件。
  11. 15 个拒绝码显示英文原文：含面板新建核心小节必现的那个。

四、必须披露的限制

这些不是「以后优化」，是本轮没有验证或有意不做的部分，请据此判断能否上线。
  • 没有真实浏览器验收：全部 UI 结论来自组件级测试（真实 hook / 重渲染 / fetch 桩）。遮罩层级、滚动、键盘可达性未在真实浏览器确认。
  • 仅 Windows 11 + Node 24.14.0 实测；Linux、Node 20、最低 DSH 0.2.0 组合未跑。
  • 未做 CI（按你的要求取消 O-08）：无远端 Node/OS 矩阵，无工作流文件。
  • 没有计费实验：不承诺 token 或费用节省；工具声明字符数不等于账单。
  • 外部编辑器不遵守本插件锁：同毫秒窗口的竞争写仍可能撞车，只能靠备份恢复，不能避免。
  • 保守降级范围较宽：主题正文里加一句说明、一个 H3、一段代码围栏或 1 空格续行，会让整个文件退回整份兼容注入（实测 40 → 5511 字符）。删除核心小节同理（33 → 5042）。
  • 回执写入延迟随记录数线性增长：约 100 条 93 ms、1000 条 886 ms；满额后带 operationId 的写入一律拒绝，需人工清理状态目录。
  • guard 在「相对路径 + 拿不到会话 cwd」时放行：绝对路径仍拦、有 cwd 仍拦；它是防误操作栅栏，不是安全边界，也拦不住 shell。
  • 面板诊断不全：/state 未暴露 mode/states/compatibility，只有 memory_status 能给。
  • 同层工具重名会明确失败并回滚，但无自动化测试覆盖；两个引擎接管同一批文件不支持，也不提供工具前缀。
