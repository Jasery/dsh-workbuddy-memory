默认分层的通用记忆插件

给 DSH 提供轻量、可控、可恢复的长期记忆；默认使用 WorkBuddy 兼容目录，不要求安装 WorkBuddy，已有记忆直接复用。

本稿整理本次讨论的已确认取舍，并给出可评审的具体规则。批准本稿之后才编写实施计划、修改产品代码；不发布、不打 tag。

一分钟读懂

记忆文件还是原来那本记事本。区别是：不再每次把整本都递给模型，而是随身带几条底线，再附一张小目录；遇到具体问题，才翻对应的页。

像 Skill 一样渐进式披露，但不把底线藏起来。“发布前先问人”直接常驻；代理参数、历史故障、工具经验按需查询。渐进式的是细节，不是用户底线。

本稿主要处理三件事：常驻哪些内容、模型如何发现其余内容、旧文件怎样安全过渡。不增加每轮专用模型调用，不引入向量库，不另存第二份记忆。

默认分层；全文模式保留为显式兼容与排障回退。旧文件还没确认划分时是一个可见的过渡状态，不悄悄裁掉旧内容，也不假装已经完成分层。

1. 哪些已经确认，哪些仍是设计提案

状态内容
用户已确认定位是通用的 DSH 长期记忆，平衡实用性与成本，不以安装 WorkBuddy 为前提。
用户已确认保留现有 WorkBuddy 兼容目录；已有文件原地复用，不为“通用”另造默认目录。
用户已确认第一次明确写记忆时创建所需目录；纯读取不创建任何东西。
用户已确认默认“少量核心常驻＋经验按需查询”，类似 Skill 的渐进式披露；全文注入作为兼容与排障回退。
用户已确认旧文件由当前主模型给出常驻／按需划分预览，用户确认后再整理；确认前不改原文件，暂时兼容注入并明确提示。
本稿提案，待确认使用一个明确的 H2“常驻记忆”或“Core Memory”小节识别核心；不做逐条权重、访问次数或每轮智能分类。
本稿提案，待确认分层总常驻预算起点为 4000 个 UTF-16 码元：项目核心 1500、用户核心 1500、规则 500、目录与过渡说明 500。它是初始参数，不是实测最优值，也不是 token 数。
本稿提案，待确认首版旧文件整理复用面板源码编辑与用户保存确认；主模型提供草案，先不新增模型草案自动投递面板的专用通道。
留给实现者具体配置键名、内部函数拆分、缓存容量与界面样式。不得改变已确认行为；预算分配及过渡例外必须有机器测试。

“已确认”仅指对话中明确同意的方向，不表示用户已经批准本稿的全部细节。

2. 为什么选择分层，而不是另两种极端

路线实际代价决定
全文限额注入最容易兼容；低频资料长期占上下文，超限后仍要决定丢谁。读盘缓存不能消除这些模型输入。保留为回退，不作为新默认。
核心常驻＋目录＋按需读取多一层明确的选择与少量目录；相关任务可能多一次读取。底线不依赖临时检索，长尾不必常驻。用户选择的默认路线。
所有内容都只按需读取常驻最少，但模型可能连“发布前需确认”都没读到；每轮取回底线又会增加往返。不采用。不是把所有记忆都改成可选资料。

文件分层与注入刷新是两件事。首版先改变“哪些文字常驻”，不顺带承诺“写一次就省下一次完整请求”，也不把复杂历史投影作为前置条件。

3. 文件不换，识别规则要明确

3.1 仍然是一处真源

项目沿用 <cwd>/<dataFolder>/memory/MEMORY.md，用户沿用 <workbuddyHome>/MEMORY.md。默认目录不变，现有自定义路径与环境变量继续有效。备份、锁、幂等台账与可重建缓存不是第二份可编辑真源。

3.2 核心小节的确定性识别

  • 只识别代码围栏之外的 H2 标题；去除标题两端空白后，接受“常驻记忆”或不区分大小写的“Core Memory”。两者是等价别名，不同时取两份。
  • 每个目标文件必须恰有一个核心小节。空小节有效，表示当前没有核心条目；没有小节属于未划分旧文件，重复或两个别名同时出现属于歧义，均进入明确的兼容状态。
  • 核心小节采用现有完整 bullet 条目模型，可带缩进续行和嵌套条目。若包含不能可靠按条目处理的正文或子标题，保守降级并提示，不偷偷丢弃非条目文字。
  • 不根据“重要”“必须”等词自动提升条目，不根据访问次数升级常驻；新鲜程度与重要程度不是一回事。

3.3 目录是入口，不是另一份摘要

本地提取其他 H2 的原始标题，加“项目／用户”来源标签，按文件原顺序排列。标题本身可携带使用线索，但首版不自动调用模型生成说明、不另存可编辑摘要。H1 下尚未分节的记录给出“未分节内容”入口，可用全文读取或搜索访问；不得被当作不存在。

目录不包含实时字符数、更新时间和命中次数。新增一个已有主题中的经验时，不应因为计数变化而改变常驻文本。目录满额时给出固定“还有更多主题，可读取章节列表”的提示，所有标题和提示都计入预算。

3.4 日期笔记与画像

日期笔记继续不注入正文，也不逐日枚举进常驻目录。未归档日期笔记可按现有工具显式搜索；首版不承诺自动搜索归档目录，空结果不能代表归档里不存在。

分层模式不再把画像全文作为另一个隐形常驻大块：画像只作为用户目录中的只读入口。建议给现有 memory_read 增加只读 user-profile 目标，解析沿用现有画像选择规则；这个目标不能进入写入目标列表。候选不唯一时明确报歧义，不猜账号。全文回退模式保持既有画像行为。

4. 每次使用时到底发生什么

4.1 组装提示词

本地解析文件 → 判断该文件的有效模式 → 取核心完整条目与简短目录 → 加精简的使用／写入规则 → 按预算渲染。目录与内容都来自同一次文件快照，不能各自读到不同版本。

常驻规则说明：记录是数据而非高优先级命令；相关任务先查对应主题；仅在有长期价值时写入；改写前读 revision，冲突不能去掉版本强行覆盖。核心可见性不能把文件中的任意命令变成安全授权。

4.2 当前主模型按任务查询

处理“推送修改”时，模型直接看到功能分支底线，并发现“Git 与网络”主题，可以直接读该章节；主题不清楚时先做字面量搜索。命中结果已足够就不再读整章。指导中优先用小额度读取、优先当前项目，必要时再扩展到用户或日期笔记。

不启动第二个模型判断“这一轮要不要查”，不增加固定检索轮次。当前主模型仍可能漏查，字面量搜索仍可能不匹配；目录是改善可发现性的办法，不是零漏检保证。查询结果留在当前会话历史中，后续步骤可复用；压缩之后是否需要重查，取决于保留下来的信息。

4.3 在原本准备写记忆时选择去向

稳定且跨任务生效的用户偏好或项目底线放核心；具体环境、故障与操作细节放主题。继续用现有写工具的 section 参数，不新增分类工具。无长期价值的临时进度不写，密码、token 等凭据值不写，只记录必要的存放位置与状态。

核心文件存在时，不带小节的追加仍应落到普通 Notes，而不是默认升级常驻。主模型可以建议移动，但用户可以纠正。不能因核心超预算自动提炼、删除或搬走原记录。

4.4 读取与写入仍有边界

保留现有只读总闸、写入开关、守卫、跨进程锁、revision、备份、原子写与幂等链。新增的分层选择不另开写路径。工具结果必须标明截断，读取的片段不等于完整源文件，不能拿片段去整节或整档覆盖。

首版不新增泛化的重整工具或通用确认 token 框架。预览 token 只能绑定计划，不等于真人授权；需要用户确认的旧文件整理走下面的受信任面板保存流程。

5. 预算、刷新与诊断

5.1 默认预算提案

常驻组成默认额度超额行为
项目核心1500 UTF-16 码元按原顺序保留完整条目，遇到下一条放不下即停止；留出固定告警文字的位置。
用户核心1500 UTF-16 码元同上。项目与用户分别保留额度，不互相挤占。
精简规则500 UTF-16 码元使用独立的精简规则模板，不截掉关键安全／查询指引。模板不合预算时测试失败，不能上线。
所有目录、画像入口与过渡说明500 UTF-16 码元按项目、用户、画像固定顺序加入完整入口，留出“还有更多主题”的提示位置。

总计 4000。标题、来源标签、分隔符、包装和告警全部计入所属额度；不允许结构行免费超预算。不切断完整条目，不产生半个 UTF-16 代理对。首版不把未用额度借给其他块，优先保证行为可解释。

仅新增“注入模式”和一个“分层总常驻预算”设置；总预算按上述固定比例分配，整数取整后的余数归目录。建议总预算范围 4000–20000；规则模板必须在最小配置下完整容纳。既有各块开关继续生效。旧的分块全文 limits 在全文／兼容路径继续使用，界面与文档明确其适用模式，不偷偷把存量自定义值解释为新的核心预算。

这是对本插件贡献的限制，不是整个 DSH 提示词、工具 schema 或整段会话的总限制。工具读取结果、模型输出和历史会话成本另计。处于旧文件兼容状态时，旧正文可能超过上述分层预算，必须在诊断里显式区分，不能宣称已受到 4000 上限保护。

5.2 先稳定文本，不抢做复杂缓存策略

本稿不改变现有刷新设置的默认语义。已有主题内新增长尾内容但标题不变时，核心与目录应逐字不变；修改核心或主题标题时，正常刷新。移除常驻提示中的实时计数，数字放诊断工具和面板。

按轮冻结若后续引入，必须先按 session／turn 隔离，不能继续只用 cwd 共享快照；它不是本版分层的前置条件。文件缓存只优化本地 I/O，并应有有界容量；不把“少读盘”等同于“少付模型费用”。

5.3 必须看得见的状态

按文件显示：配置模式、有效模式、兼容原因、核心是否歧义或超额、原文有多少条未常驻。按会话显示最近一次实际装配的各块字符数、是否截断；尚未装配时为 null，不用估计值冒充实测值。所有输出使用 lossless JSON。

这些指标不写进常驻目录。用户打开诊断时再读详细数字，避免“为了显示状态”反而不停改变提示词。

6. 旧文件过渡：默认分层，不等于擅自重写旧记忆

文件状态有效行为原文件是否改变
不存在只读返回未初始化；首次合法写入按新格式建立文件。只读不创建。
恰有一个有效核心小节默认使用分层；其他内容按需。读取不改动。
旧文件没有核心小节该文件暂时兼容全文限额注入，明确显示“待确认划分”；其他已划分文件仍分层。不自动添加标题或重排。
核心重复、结构歧义该文件兼容注入并标出原因，不只读第一处假装成功。不自动合并。
用户显式选择全文模式全部目标采用旧的限额注入方式，用于兼容与排障。不删除已存在的核心小节。

6.1 草案由当前主模型给，不后台付费整理

用户明确要求整理时，当前主模型读取完整目标，提出“拟常驻内容／拟按需内容／必要的主题标题调整”，并给出修改草案。不是安装时自动调用模型，也不是每轮跑一次；内容太大、未读全或用户不想整理，就继续兼容状态。

首版只做划分：尽量移动完整条目，不顺带删除、压缩、改写事实；如确需改写，单独标明差异并由用户决定。单个项目文件与单个用户文件分别处理，不做跨文件事务，不把同一条记录同时保留为两份可编辑正文。

6.2 用现有面板完成一次真实确认

  1. 主模型在会话中给出完整草案，并单独附上来源目标与读取时的 baseRevision；用户将正文和基线 revision 一起填入面板草案预览。首版不自动投递草案，也不增加后台模型入口。
  2. 面板先校验草案 baseRevision 与读取到的源文件一致，再展示该快照与草案的整档差异；基线缺失或不一致即拒绝导入，不自动把旧草案换绑到最新 revision。差异视图与基线输入是需要补的能力，不能把当前编辑器已有功能夸大为已提供。用户点击保存／应用才发起写入。
  3. 保存强制携带同一个基线作为 expectedRevision，并带幂等键，使用同一 store。预览后文件变动、源文本被截断、写入被关闭或没有真人点击，都不能应用旧草案；冲突只允许重新读取、由主模型基于新快照重做草案并重新预览，不能走“移除 revision 后覆盖”。
  4. 保留完整备份与恢复入口。成功后从原文件重新识别核心小节，该文件变为分层；不另存“已确认”影子正文。

复用现有 replaceDocument 动作意味着必须先补强它的强制版本检查；源码编辑器的旧“冲突后无 revision 覆盖”出口也需收紧，不能绕过此要求。确认按钮不是权限边界：面板继续接入宿主 connection.requestRejection 信任栅栏，并共用存储校验。

没有 Web 面板、面板只读或源码编辑被关闭时，不放宽权限；保留草案和兼容状态，用户可通过可信本地编辑器自行确认修改。首版不为 headless 新造授权框架。

待确认提示采用固定、非阻断文字；不每轮弹窗催迁移。用户拒绝或略过，不视为允许整理。

7. 首次使用与惰性初始化

读不创建，写才创建。安装、注入、状态查询、搜索、读取，都不创建记忆目录、空文件、备份目录或持久状态目录。缺文件是正常状态，不要求先安装或登录 WorkBuddy。

只有经过只读／写入开关、目标解析、参数与内容校验的合法写入，才按既有配置解析路径，创建必要目录与文件；无 cwd 时不能拿进程目录凑项目路径。拒绝或无效写入也不应留下初始化垃圾。

新建长期记忆文件时，写入语言对应的 H1、一个空核心小节，再把首条内容放进调用指定的小节；未指定小节仍为普通 Notes。若第一次就明确写核心，则追加到已有的空核心小节，不再创建同名标题。日期笔记仍按日期格式，不顺带制造长期记忆或画像。

已有任意目录或文件直接复用；已有旧文件不能因普通追加就被自动插入核心小节，从而跳过用户确认。普通 append／edit／replace-section 等写工具不得将一个尚未划分或有歧义的旧文件变成有效分层文件：尤其 append 指定缺失的保留核心标题时，必须返回“需要先确认划分”，不落盘，不自动创建该标题。新偏好可由主模型另行写到普通 Notes 或主题中，不能静默改写调用目标来伪装成功。此限制只针对已有旧文件；不存在的目标仍按新格式合法初始化。

该转换检查必须在同一写锁内依据当前原文与拟写正文执行，不能只在工具入口读一次后做判断。已确认分层文件的正常核心追加不受此转换限制，仍受预算提示与原有写入校验约束。用户经可信本地编辑器自行改格式，或按已有授权恢复一个历史备份，分别按显式编辑／恢复规则处理，不把它们当成后台自动迁移。只创建本次目标确实需要的目录与状态，不创建 USER、IDENTITY、SOUL 或第二套默认目录。

如果保留现有 ensureLayout 配置，建议新默认开启，显式 false 仍表示拒绝自动建目录；它仅约束写入，不能被用作“读取时顺便初始化”的理由。

8. 首版范围与原优化清单的关系

首版包含明确不顺带做

旧文件草案＋面板差异与用户保存；强制 revision；原备份恢复链。自动重整、冷却期系统、通用确认 token 框架、后台草案投递。
与改造同步的回归测试、只校验不发布的 CI、真实成本／效果对照。按轮冻结作为首发强依赖、静默预设掩码、同装工具前缀。

原 11 项优化方案保留作历史分析材料，本稿不是把它全部打包进首发：O-01 改为硬预算与完整条目，不承诺“文件尾＝最新”；O-03 先补高影响替换的版本与真实确认；O-06 的缓存收益按路由实测；O-07／O-08 前移为改造护栏。全文回退仍保持可控截断，但不把一次性全面翻修旧模式作为分层前提。

建议实施次序：先固定纯解析、预算与拒绝路径的不变量，再接入注入／诊断和合法首写，再做面板差异与旧文件过渡，最后跑任务效果与成本对照。此处是依赖说明，不是已批准的实施计划。

9. 怎么证明它值得做

9.1 工程验收

场景必须满足
正常分层核心可见，长尾正文不常驻，目录与源快照对应；项目与用户来源可辨认。
只改已有主题里的经验不改核心／标题时，常驻装配文本逐字相同；不混入 mtime、字符数等抖动。
预算边界各块与总预算均不超限；标题和告警算预算；不切断条目和代理对；超额状态可见。
核心识别中英文别名、空核心、围栏内伪标题、重复核心、非条目正文分别有测试。
旧文件／混合状态无确认不重排原文，普通主题追加可继续；普通写工具不得创建／修复核心小节从而暗中把旧文件切到分层。项目分层＋用户兼容可同时出现；兼容原因与真实字符数可查。
首次使用纯读前后文件系统无新增；无效／被拒绝写入不建目录；合法首写只初始化必要目标。
确认与冲突只有草案没有真人保存时不写；缺 revision、旧 revision、截断源、重放、只读均按约定拒绝或幂等；备份可恢复。
并发与会话不同 cwd 的读写不串项目；同 cwd 多会话不会错报别人的装配快照；同一基线 revision 并发改写不能无声覆盖。
画像与读取分层不隐式常驻画像全文；只读目标可访问唯一画像，写工具拒绝画像；歧义不猜选。工具截断不能冒充完整读取。
降级文件不可读、无法识别、无 Web 面板、关闭权限均不阻断正常对话，也不自动扩权。所有工具结果为 lossless JSON。
CI 与发布PR 跑相关测试与预算断言；不增加自动 npm publish、Release 或 tag 动作。最低宿主版本需单独验证，不能用当前安装结果代替。

9.2 效果与成本对照

使用同一批约 20 个固定任务，对照全文模式与完成确认后的分层模式：稳定偏好是否遵守；大量追加后底线是否仍可见；旧故障经验能否找回；无关任务是否避免无用读写；不同项目是否隔离。先记录基线，再比较，不先编“节省百分比”。

同时记录实际常驻字符、工具往返与回显长度；按同一路由记录可取得的输入／输出 token、cacheRead／cacheWrite 与延迟。提供方没有返回的数据写 null 并说明未知，不用字符数推算成精确费用。查询结果的历史累计、一次性整理和本地 I/O 单独列出。

保守验收底线：固定测试中的常驻底线不得漏注入或违反；长尾查回能力不能因分层静默变差。若频繁取回大半本文件，或额外往返抵消收益，就收紧目录／检索范围或调整预算，而不是宣称“分层一定更便宜”。

10. 已核对证据、风险与回退

本次设计依据的现有实现
  • paths.js：已有路径配置与 WorkBuddy 兼容目录，不需要新造存储根。
  • store.js：当前首写在 ensureLayout 关闭且缺目录时拒绝；本稿改变默认首次使用行为，不假装已经具备。
  • markdown.js：已有章节追加在章节末尾，而非全文件末尾；因此尾截不保证最近写入。
  • read.js与search.js：已有章节目录、章节读取与字面量搜索；画像目标与分层预算仍需新增实现。
  • 整档替换与面板截断保护：替换已共用 store，但强制 revision 与迁移差异确认仍需补齐。
  • inject.js：现有冻结按 cwd、失效全清；如后续做按轮冻结，必须单独修正作用域。

当前核对的安装版本为 DSH 0.2.2-rc.3。其系统提示词文档说明：支持 systemPromptUpdate: in-history 的路由可在同一请求序列追加提示词更新；其他路由可能重写头部；历史内更新又会累积提示词版本。不据此承诺所有模型都命中缓存，也没有验证旧的最低支持版本已具备同样能力。

主要剩余风险是主模型漏查、标题不够好、用户把太多内容放常驻、旧文件长期停在兼容状态，以及双模式增加维护成本。对应措施是有界入口、明确诊断、任务对照与显式全文回退；不是再堆一个自动后台系统。

回退只改变注入选择，不自动还原或删除已整理文件。原文整理错误走现有备份恢复，恢复本身仍需当前 revision；独立文件分别回退，不能承诺跨文件原子恢复。
